1

Check requirements

Run this in your front-end project to confirm the Vue version. Vue 2 and Vue CLI 4 (webpack 4) are not supported.

terminal · your app
npm ls vue
The output shows vue@3.3 or later.
2

Build the package

in the editor repository — E:\Samsung\Editor
terminal · editor repo
npm install
npm run build
npm run pack
The file packages/editor/local-rich-editor-0.1.0.tgz exists.
3

Install it in your app

Copy the .tgz into your project (for example a vendor/ folder) and install it. The path in package.json then works for every developer and in CI.

terminal · your app
npm install ./vendor/local-rich-editor-0.1.0.tgz
npm ls vue
Only one copy of vue is listed; the editor’s copy is marked “deduped”.

Seeing two copies of Vue? Add resolve: { dedupe: ['vue'] } to vite.config.ts, delete node_modules/.vite, and restart the dev server.

4

Import the styles once

src/main.ts
main.ts
import '@local/rich-editor/styles.css'

All editor class names start with re- and the stylesheet sets no global styles, so it won’t change the rest of your dashboard.

5

Add the editor to a page

any .vue page, e.g. src/views/DocumentEdit.vue
DocumentEdit.vue
<script setup lang="ts">
import { ref } from 'vue'
import { RichEditor } from '@local/rich-editor'

const content = ref('')
</script>

<template>
  <div style="height: 80vh">
    <RichEditor v-model="content" layout="document" height="100%" />
  </div>
</template>

The editor fills the space it’s given. Give the container a height, or use :height="400" for a fixed size or height="auto" to grow with the content.

The toolbar appears and you can type, format text and insert a table.
6

Load and save content through your API

Render the editor only after the document has loaded. Store HTML (the default), or add content-format="json" to store JSON.

DocumentEdit.vue · script
const loading = ref(true)
const savedContent = ref('')

onMounted(async () => {
  content.value = (await api.get(`/documents/${id}`)).html
  loading.value = false
})

// The editor normalises HTML on load; use its first output as the saved state.
function onReady(editorApi: RichEditorExpose) {
  savedContent.value = editorApi.getHTML()
}

async function save() {
  await api.put(`/documents/${id}`, { html: content.value })
  savedContent.value = content.value
}
DocumentEdit.vue · template
<RichEditor v-if="!loading" v-model="content" @ready="onReady" />
<button :disabled="content === savedContent" @click="save">Save</button>
Save, reload the page, and the content comes back unchanged.
7

Connect image uploads to your backend

Without this, images are embedded in the content as base64, which makes every save large. Your function uploads the file and returns its URL.

DocumentEdit.vue
async function uploadImage(file: File) {
  const form = new FormData()
  form.append('file', file)
  const res = await fetch('/api/uploads/images', { method: 'POST', body: form })
  if (!res.ok) throw new Error('Upload failed')
  return (await res.json()).url
}

// template
<RichEditor v-model="content" :upload-image="uploadImage" @error="onError" />
  • A preview shows immediately and is replaced by your URL when the upload finishes. If it fails, the image is removed and error fires.
  • Allow your app’s origin in CORS on the image host; Word export downloads each image to embed it.

Follow your dark mode by passing :theme="isDark ? 'dark' : 'light'", or use theme="auto" to follow the operating system.

9

Configure it for the page

template
<RichEditor
  v-model="content"
  toolbar="basic"
  :editable="canEdit"
  :features="{ images: true, tables: true, docx: true }"
  page-size="A4"
  document-name="report"
/>
  • toolbar: 'full', 'basic', 'none', or your own groups such as [['bold','italic'], ['table']].
  • editable: set to false for read-only; the toolbar hides.
  • features is read when the editor mounts. Change the component’s :key to apply new values.
10

Add Word export where you need it optional

The toolbar’s File menu already opens and downloads .docx. To use your own buttons, call the editor through a template ref.

DocumentEdit.vue
const editorRef = ref<RichEditorExpose>()

// download to the user's computer
editorRef.value?.download('docx', 'report')

// or get the file and send it to your server
const blob = await editorRef.value!.exportDocx()

// template
<RichEditor ref="editorRef" v-model="content" layout="document" />

For list pages that export without showing the editor, use import { exportDocx } from '@local/rich-editor/docx' with JSON content.

11

Add the AI Canvas with Gemini optional

Users generate a draft, then change only the part they point at. Every AI change is a suggestion to accept or reject. The Gemini key stays on a server; the editor only calls your own /api/ai endpoint.

examples/ai-server (settings in one file: gemini.config.ts)
terminal · AI server
cd examples/ai-server
npm install
cp .env.example .env   # set GEMINI_API_KEY
npm start              # or: npm run mock (no key, demo answers)
vite.config.ts · route /api/ai to the server
const aiServer = { '/api/ai': { target: 'http://localhost:8787', changeOrigin: true } }
export default defineConfig({ server: { proxy: aiServer }, preview: { proxy: aiServer } })
DocumentEdit.vue
import { RichEditor, createHttpAiAdapter } from '@local/rich-editor'

const aiAdapter = createHttpAiAdapter({ url: '/api/ai/complete' })

// template
<RichEditor v-model="content" :ai="aiAdapter" @error="onError" />
  • An AI menu appears in the toolbar, Ask AI under selected text, and Ctrl+J opens the AI bar.
  • Chat with the document (toolbar button or Ctrl+Alt+J): answers link to their sources, and requested changes appear as suggestions. Bind v-model:chat-history to keep the conversation per document.
  • Pending suggestions aren’t in v-model, so your save logic doesn’t change.
  • In production, route /api/ai through your reverse proxy with buffering off, and require your dashboard’s login on it.
GET /api/ai/health returns "ok":true, and selecting text then choosing Make shorter shows a suggestion.
12

Secure the content

The editor strips unknown markup, but your API can still receive anything a user sends.

  • When saving: sanitise HTML on the server with an allow-list sanitiser (DOMPurify, bleach, HtmlSanitizer or OWASP).
  • When displaying outside the editor: sanitise before v-html.
  • Uploads: check file type and size on the server, and sanitise or reject SVG files.
display page
import DOMPurify from 'dompurify'
const safeHtml = computed(() => DOMPurify.sanitize(doc.value.html))

// template: the editor's content styles, without the editor
<article class="re-export re-content" v-html="safeHtml" />

Test before release

Work through the checklist below on a real page of your app. Your ticks are kept in this browser.

Release checklist

If something doesn’t work

SymptomFix
No styles, broken toolbar layoutImport @local/rich-editor/styles.css in main.ts (step 4).
Editor collapsed or no scrollbarGive its container a height, or use height="auto" (step 5).
“Invalid VNode type” or inject() warningsTwo copies of Vue. Add resolve: { dedupe: ['vue'] } and clear node_modules/.vite.
Can’t find @local/rich-editor/docx typesSet moduleResolution to "bundler" or "node".
Dropdowns hidden behind your header or modalLower the editor’s layers: .re-popover { z-index: 3000 }, .re-modal-backdrop { z-index: 3100 }.
Brand colors missing in dropdownsAdd .re-portal to your variable selector (step 8).
Images missing from the Word fileThe image host blocks CORS. Allow your app’s origin (step 7).
First Word export reloads the page in developmentAdd optimizeDeps: { include: ['docx', 'mammoth', 'marked', 'turndown', 'turndown-plugin-gfm'] } to vite.config.ts.
AI bar says Change the component’s :key to remount it.
